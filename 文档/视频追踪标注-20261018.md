# 视频追踪标注

本功能已加入本地源码。已发布的 0.4.1 EXE/DEB 尚未重新打包。

## 使用方法

1. 左侧进入“视频追踪标注”。选择已有项目，或点“新建标注项目”设置任务、类别与骨点模板。
2. 选择视频、起止时间和保存间隔，点“导入视频，标注首帧”。默认每 0.2 秒保存一张图片；所有原始帧仍会参与追踪。
3. 在画布中标全该帧目标。姿态任务需完成骨点，无法定位的点按 K 跳过；可判断位置的遮挡点标记遮挡。
4. 点“保存并开始追踪”。自动结果写入当前项目的 `images/` 和 `annotations/`，并保留视频帧号、时间、起始人工标注及算法来源。
5. 若自动暂停，会打开问题帧，不为该失败帧生成标注。重新标注后点“保存当前帧并继续”。
6. 目标完全消失时，可点“前进 1 秒”寻找重新出现的目标；该操作只保存画面，不凭空生成标签。
7. 自动结果为待审核，检查并确认无误后才进入训练数据。未经审核的自动帧不能直接作为下一次追踪的起点。

手动暂停与退出都会保留已有结果。视频列表保留进度；继续追踪需要原视频仍在导入时的位置。相邻视频帧高度相似，训练集和验证集应尽量使用不同视频，避免评估偏高。

## 追踪与暂停规则

- 本地 OpenCV 金字塔 LK 光流、前后向一致性检查、RANSAC 相似变换和灰度外观相关性，无需网络或模型下载。
- 每个目标独立估计运动；任一个目标不可靠，整段任务暂停。原有类别、姿态实例编号、物体遮挡标志与骨点可见性保留。
- 可见骨点单独计算局部光流，并检查局部外观；遮挡骨点跟随实例整体变换，仅作为待审核的位置估计。跳过点始终不补造。
- 特征大量丢失、目标出画、画面差异过大、位移/尺度变化过大、与上一帧或起始帧的外观不匹配时暂停。
- 严格/均衡/宽松三个档位控制外观、位移和前后向误差阈值；均衡为默认。阈值是启发式判断，不能保证识别所有漂移。
- 最长每 30 秒或每轮 500 张自动帧停下检查，限制累计误差。达到用户所选结束时间或视频结尾则完成。
- 已存在的图片或标注不会被追踪任务覆盖；遇到时暂停，要求检查当前内容后再继续。
- 追踪运行期间锁定画布与编辑工具；后端也拒绝保存/移除标注、切换项目或启动训练。Esc 可请求暂停。

支持目标检测、姿态、分割和旋转框。分割轮廓通过实例整体运动传播，不能替代逐像素形变追踪。整图分类使用原有视频抽帧入口。

新目标进入画面不会被主动检测；类别尤其是动作类别不会自动改变。需要手动暂停补标或改标签。相似目标交叉、大面积遮挡、快速运动、低纹理和复杂形变可能引起暂停或漏检漂移，仍需审核。

## 界面方案与检查范围

沿用现有色板：画布 `#0a0c10`、背景 `#0f1116`、面板 `#1c1f27`、正文 `#eef1f6`、辅助文字 `#aab2c0`、操作强调 `#f1b34c`；浅色使用现有主题变量。字体沿用 Segoe UI / Microsoft YaHei UI。

独立页面左侧导入表单、右侧视频进度列表；标注时共享现有画布，在上方保留一条状态与续跑操作栏。文字左对齐，灵敏度放在折叠设置中。避免把视频表单继续堆进骨点侧栏。

```text
视频追踪标注
导入视频与保存间隔       已导入的视频 / 进度

标注画布
当前状态 / 原因          暂停 / 保存并继续
图片列表                画布                 类别与骨点
```

验收清单：独立入口和新建项目衔接；首帧按需导入；空标注拒绝；自动传播；切镜/丢失/跳变暂停；修正续跑；已有标注保护；待审核状态；前进找目标；手动暂停；重载恢复；深浅色和 1050×700 窗口；可见/遮挡/跳过骨点的传播。

## 文件与复现

- `desktop/video-tracking.js`：独立视频入口和画布操作栏。
- `anylabeling/services/workflow/tracking.py`：算法、会话、存储和暂停逻辑。
- `tests/workflow/test_tracking.py`：真实视频编解码与算法回归测试。
- `desktop/video-tracking-qa.cjs`：真实 Electron 鼠标操作，使用隔离合成视频。
- 修改前备份：`备份/20261018-172109-video-tracking/`，8 个已有文件均经 SHA256 校验。

开发者可运行 `npm --prefix desktop run check`、`npm --prefix desktop test`；在 `X-AnyLabeling` 目录用项目 Python 运行 `python -m pytest tests/workflow -q -o addopts= --basetemp=../.runtime/新测试目录`。

桌面验收使用 `XAL_ELECTRON_QA=1`、`XAL_QA_TRACKING=1` 和绝对路径 `XAL_QA_TRACKING_ROOT`，测试目录中准备 `cut.avi` 与 `long.avi`。合成素材用于功能验收，不属于用户训练数据。
