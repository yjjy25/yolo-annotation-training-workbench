## 1. 产品目标与开发路线

基于 X-AnyLabeling 扩展一款中文桌面软件，让用户在同一个项目中完成：

**导入图片 → 定义类别与骨点 → 少量人工标注 → CPU/GPU 训练 → 自动预标注 → 人工微调 → 再训练 → 导出模型。**

建议采用“保留原标注能力，增加新手工作流和训练中心”的路线。熟悉原软件的用户仍能使用原有操作，新手只需跟随步骤按钮。首版必须把目标检测和自定义姿态估计完整做通，再逐步扩展分割等任务。

## 2. 面向新手的整体界面

### 2.1 首页只提供六个主要入口

| 入口 | 用户能做什么 |
| --- | --- |
| 新建/打开项目 | 选择任务、图片目录、保存位置 |
| 开始标注 | 人工标注，自动保存，继续上次进度 |
| 训练模型 | 选择 CPU/GPU、模型及训练参数 |
| 自动标注 | 选择训练结果，批量生成待审核标注 |
| 审核与微调 | 优先查看可疑结果，拖动修正，一键进入下一张 |
| 模型与导出 | 查看训练历史、试用模型、导出权重和数据 |

项目页固定显示流程条：`①导入 → ②定义标签 → ③人工标注 → ④训练 → ⑤自动标注 → ⑥审核/迭代`。每一步都有一个明确的“下一步”按钮。

### 2.2 两种操作模式

- **新手模式，默认开启**：只显示必要选项，内置说明、推荐配置、示例项目和操作提示；用户无需手写 YAML 或输入终端命令。
- **专业模式**：展开完整参数、数据版本、日志、运行环境和模型适配设置。

所有重要提示都包含原因和可点击的处理动作。例如：“显存不足，可减小批大小。［用较小批大小重新训练］”。保留技术日志供排错，首页不直接展示大段堆栈。

### 2.3 第一次使用的引导

1. 选择“画目标框”或“标骨点”。
2. 选择图片文件夹；显示可读图片数、损坏图片数和已有标注数。
3. 输入类别；姿态项目选择或新建骨点模板。
4. 跟随一张教学图片完成首次标注。
5. 标注一批代表性图片后，点击“训练第一个模型”。
6. 在小批图片上预览自动标注效果，再运行批量任务。

每个页面提供“这一步做什么”和“恢复推荐设置”，无需理解深度学习术语也能完成流程。

## 3. 核心功能：方便的自定义姿态标注

### 3.1 自定义骨点与骨架模板

用户可以完全自定义：

- 骨点数量、中文名称、稳定 ID、标注顺序与颜色。
- 骨点之间的连线、分组、左右对称配对。
- 每个骨点的可见、遮挡但位置可判断、位置未知状态。
- 模板名称、版本、示意图以及说明。

模板既可以从名称列表建立，也可以在示意图上点选位置，再点击两个骨点连接骨架。支持拖动排序、复制模板、导入导出 JSON。可提供人体、手部、动物等参考模板；参考模板不代表已有相应领域的预训练模型。

例如，自定义“机械臂”模板：`底座中心 → 肩关节 → 肘关节 → 腕关节 → 夹爪中心`，连线由用户指定，不限制为人体。

**同一个训练数据集默认使用同一套骨点数量与语义顺序。** 不同类别如需不同骨架，首版引导拆分成独立姿态项目；后续再评估统一骨点映射。界面能编辑某种骨架，不等于所有模型都能直接训练该骨架。

### 3.2 实际标注操作

1. 选择类别，画出一个目标框，明确该实例的范围。
2. 点击“开始标骨点”，右侧高亮当前应标注的骨点名称。
3. 按顺序点击，自动切换到下一个骨点，并按模板连线。
4. 不确定位置时选择“位置未知”；能判断但被挡住时选择“遮挡”。
5. 点错时撤销；完成后直接拖动骨点微调，整套骨架可以整体移动。
6. 确认该实例；多目标图片继续添加下一个实例，骨点不会跨实例连接。
7. 完成整张图后标为已审核，自动进入下一张待处理图片。

姿态框可手动调整；根据骨点拟合范围只能作为辅助建议，不能把点的包围范围直接当作完整物体范围。

### 3.3 减少操作次数的设计

| 功能 | 具体行为 |
| --- | --- |
| 顺序点选 | 一次进入姿态模式即可连续点完全部骨点 |
| 智能提示 | 当前骨点名称、左右侧颜色、局部放大镜始终可见 |
| 快捷键 | 建议 `Space` 临时拖动画布、`Tab` 切换骨点、`Ctrl+Z` 撤销；实施时核对原软件快捷键冲突 |
| 缺失点处理 | 明确区分“遮挡”和“未知”，避免强迫用户乱点 |
| 左右纠错 | 交换成对骨点标签，提供对象左右与屏幕左右的说明 |
| 复制骨架 | 复制上一张/上一个实例的布局，移动缩放后修正；复制结果仍待确认 |
| AI 微调 | 模型提供框和骨点，用户只需拖动错误位置、补漏和删除误检 |
| 自动保存 | 编辑事务完成后保存；提供撤销、备份和异常恢复 |

模板修改需要版本管理：仅改显示名可保持稳定 ID；增加、删除或调整骨点顺序时生成新版本并执行显式迁移。旧模型不能直接用于语义不一致的新模板。

### 3.4 导出与训练前校验

自动生成姿态训练所需的标签和数据配置，校验目标框、骨点数量、顺序、坐标范围及左右映射。采用三维骨点表示时，界面状态映射为 `v=0` 未标注/位置未知、`v=1` 有位置但遮挡、`v=2` 可见；未知点不能参与正常位置监督。

数据配置写入 `kpt_shape: [K, 3]`；已定义左右配对时生成 `flip_idx`。未配置合法映射时关闭水平翻转，不能默认把骨点顺序反转。骨架连线与语义名称另存为项目元数据，随模型一起导出，避免只有权重却丢失骨点含义。

训练标签结构依据 [Ultralytics 姿态数据格式](https://docs.ultralytics.com/datasets/pose/)，具体字段以锁定后端版本的实际支持为准。

## 4. 训练中心：CPU/GPU 可选，参数可填写

### 4.1 设备选择

提供“自动推荐 / CPU / 指定 GPU”。自动推荐先检测可用设备并执行短检查，显示设备名称、驱动兼容性和可用显存；不以“检测到显卡”代替“训练后端可用”。

| 情况 | 软件行为 |
| --- | --- |
| 没有可用 GPU | 允许 CPU 训练，提醒耗时可能较长，推荐小模型和小批量 |
| NVIDIA GPU + 后端检查通过 | 可选择单张 GPU，显示设备编号与名称 |
| 有显卡但后端不可用 | 显示具体原因和修复入口，仍可选 CPU |
| AMD / Intel 显卡 | 不承诺首版通用 GPU 训练；按系统和适配器实测能力开放，否则使用 CPU |
| 用户手动指定 GPU 失败 | 清楚报告失败，不静默改为 CPU 长时间训练 |

首版验收 CPU 与单张 NVIDIA GPU，后续扩展多卡。训练与批量预标注共用设备调度，默认排队，避免两者同时占满显存。

### 4.2 新手参数页

| 界面名称 | 参数 | 建议初值/规则 |
| --- | --- | --- |
| 训练模型 | 模型家族、规模及初始权重 | 推荐已通过验证的小模型，支持选择本地权重 |
| 训练设备 | device | 自动推荐，可明确切换 CPU/GPU |
| 学习轮数 | epochs | 示例 100；提供快速试跑和正式训练配置 |
| 图片尺寸 | imgsz | 示例 640，检查模型步长限制 |
| 每批图片数 | batch | 根据设备短测给出建议，允许手动修改；自动模式仅在后端支持时开放 |
| 学习率 | lr0 | 展示当前推荐值与作用，允许覆盖 |
| 提前结束等待轮数 | patience | 可填写，解释“验证效果连续不改善时结束” |
| 数据划分 | train/val/test | 推荐 80%/20% 作为初始训练/验证比例，正式评估另留测试集 |

比例不是硬规则。小样本导致某类别没有验证样本时必须提示；关联视频、同一对象或同一采集场景应按来源分组划分，避免相邻帧泄漏。

### 4.3 专业参数页

按“优化器、增强、性能、姿态、输出”分组展示当前模型真正支持的参数，例如优化器、学习率调度、权重衰减、预热、随机种子、workers、缓存、AMP、mosaic、mixup、旋转、翻转以及姿态损失权重。

所有参数都有中文解释、取值范围、恢复默认和冲突校验。未知参数、模型不支持的参数直接报错，不静默忽略。保存为训练配方 JSON/YAML，供下次复用；界面展示与实际提交配置保持一致。预标注置信度不混入训练超参数。

### 4.4 训练过程与结果

- 启动前执行路径、数据、骨点、模型权重、运行环境和磁盘空间检查。
- 主界面持续可用，显示轮数、损失、验证指标、设备资源和日志。
- 预计剩余时间在已有足够采样后给出，标注为估计值。
- 提供“停止并保留已有检查点”，不把停止包装成无损实时暂停。
- 支持从可恢复检查点继续训练；更换数据版本后作为新一轮训练处理，不冒充原运行续训。
- 保存最佳权重、最后检查点、配置、数据快照 ID、后端版本和指标。
- 姿态模型同时展示框与关键点评估结果，自定义骨架说明所用关键点评估配置，避免跨不同骨架直接比较分数。
- 结果页直接提供“试用模型”和“用此模型自动标注”，用户不用寻找训练输出目录。

训练接口和参数设计参考 [Ultralytics 训练文档](https://docs.ultralytics.com/modes/train/)。

## 5. 多种 YOLO 模型兼容策略

“多模型兼容”必须落实为经测试的模型、任务和运行环境组合，不能只让用户输入任意模型名称。以下是开发目标，尚非已通过的支持清单。

| 模型家族 | 第一优先任务 | 开发阶段 | 说明 |
| --- | --- | --- | --- |
| YOLOv8 | 检测、姿态 | 首版必须 | 用作首个完整闭环与回归基准 |
| YOLO11 | 检测、姿态 | 首版必须 | 复用统一后端接口，分别验证 |
| YOLO26 | 检测、姿态 | 首版扩展目标 | 以固定依赖版本的真实加载、训练与推理测试为准 |
| YOLOv5 | 检测 | 后续扩展 | 评估独立适配器与环境，不承诺任意 v5 权重可直接通用 |
| 其他 YOLO 家族 | 按适配器确定 | 后续扩展 | 不默认都有姿态分支，先验证任务再开放 |
| 自定义权重 | 与模型结构匹配的任务 | 首版支持已验证家族 | 校验类别、骨点定义、后端及元数据 |

每个适配器声明：支持任务、权重格式、参数、依赖版本、设备能力和导出格式。模型目录仅展示当前项目可用组合；不支持项解释原因。

**训练与推理分开判断：** ONNX 等推理格式通常不能作为继续训练检查点；PT 扩展名相同也不代表模型结构兼容。自定义骨点可以通过匹配的数据与模型配置训练，人体预训练模型不能直接准确预测任意动物或机械结构。相关任务依据 [Ultralytics 姿态文档](https://docs.ultralytics.com/tasks/pose/)，支持状态最终以本项目测试矩阵为准。

## 6. 少量人工标注 → 自动标注 → 人工微调

### 6.1 新手操作流程

1. 导入全部图片，建立类别和骨点模板。
2. 软件建议先选一批有代表性的图片，覆盖类别、角度、遮挡和场景。可先尝试 50～200 张做流程验证，但不保证这些数量足以训练出可用精度。
3. 人工完成并审核种子数据；从人工审核数据中固定划分训练集和验证集，正式测试集单独锁定。
4. 点击“训练初始模型”，先运行短试跑检查数据和环境，再正式训练。
5. 点击“预览自动标注”，在少量未标注图片上检查误检、漏检和骨点顺序。
6. 点击“批量自动标注”，默认处理剩余未审核图片；可选择全量重新推理，但已有人工结果只生成对照候选，不覆盖原标注。
7. 打开“待审核”列表，先看可疑结果，修正框、类别和骨点，确认整张图无遗漏。
8. 将新审核数据加入下一轮训练集；保持验证/测试划分锁定，比较新旧模型。
9. 重复迭代，直到满足项目自己的精度要求或人工审核完成。

### 6.2 数据状态与保护

| 图片审核状态 | 是否进入默认训练集 |
| --- | --- |
| 未标注 | 否 |
| 人工编辑中 | 否 |
| AI 预标注，待审核 | 否 |
| 人工审核通过 | 是，但仍遵守 train/val/test 所属划分 |
| 明确确认的无目标图片 | 可作为负样本，按当前训练后端规则导出 |
| 已排除/损坏 | 否 |

“AI 来源”和“人工来源”另作为实例级元数据保留；审核通过后也不抹去原模型、置信度及修改历史。一次批量任务记录模型 ID、阈值、时间与输入图片清单，可撤销本轮候选结果。

批量预标注任务保存进度，支持取消和继续；候选结果与正式标注分层保存。若任务过程中人工改动同一张图，提交候选时检测版本冲突并提示合并，不能覆盖刚完成的修正。

### 6.3 让人工审核更省力

- 支持按类别、低置信度、缺点、异常骨架和来源筛选。
- 默认优先展示低置信度、检测为空及骨架异常图片；置信度高也不能保证无漏检。
- 提供随机抽查高置信度图片，防止只审核模型自己“不确定”的结果。
- 单图提供“通过并下一张”“需返工”“无目标”按钮；有未处理警告时避免误通过。
- 支持选择范围后批量确认，但展示数量及抽查提示；新手不默认一键确认全部。
- 可疑样本优先级不等于真实不确定性；初版采用可解释规则，后续再加入主动学习策略。

## 7. 数据管理与实用拓展

### 7.1 首版应有

- 图片与原始标注默认保留，导出到新目录；缺失标签不等同于确认的负样本。
- 类别顺序和骨点顺序采用稳定 ID 管理，修改后显式映射。
- 图片损坏、越界坐标、空框、关键点数量不符、类别缺失等一键体检。
- 文件哈希识别完全重复图片；同源视频帧通过来源信息分组。近重复检测作为后续增强。
- 训练使用不可变数据快照，训练期间继续标注不会改变本轮数据。
- 项目保存统计：图片数、实例数、各类别数量、审核状态、数据划分。
- 自动保存采用临时文件写入后替换，定期备份；保留操作历史和项目恢复入口。
- 拖入图片文件夹、最近项目、参数配方复用、内置演示数据。

## 8. 技术架构与跨平台设计

### 8.1 分层结构

```text
跨平台桌面界面：新手向导 / 原标注画布 / 骨架编辑器 / 训练与审核中心
                         ↓
项目服务：模板版本 / 标注状态 / 数据校验 / 快照与划分 / 模型注册
                         ↓
任务管理器：启动、排队、进度、停止、日志、恢复
                         ↓
独立工作进程：训练适配器 / 批量推理适配器 / 格式转换
                         ↓
按后端隔离的运行环境：CPU 或经验证的 GPU 依赖
```

优先复用上游 Python/Qt 技术栈，具体 Qt 绑定及打包工具以锁定源码为准。训练放在独立进程，通过结构化事件向 UI 回报，不占用 UI 主线程，也不在界面进程内安装和切换 PyTorch。

训练后端建议首选固定版本的 Ultralytics，通过统一的 `validate_config / train / resume / predict / export / capabilities` 接口扩展其他家族。停止任务需管理整个进程树，避免窗口关闭后留下 GPU 子进程。

项目以 JSON 保存可移植配置，以 SQLite 保存任务索引和审核状态；原始标注文件作为可恢复的数据依据，索引可重建。明确每类字段的唯一权威来源，避免数据库与 JSON 双写冲突。

### 8.2 建议项目目录

```text
my_project/
  project.json              # 项目配置、任务类型、相对路径
  project.db                # 状态索引、任务记录，可重建
  schemas/                  # 类别与骨架模板版本
  images/                   # 托管图片，或通过清单引用原始图片
  annotations/              # 正式标注与来源元数据
  proposals/                # 按任务分开的 AI 候选结果
  splits/                   # 固定划分与来源分组记录
  snapshots/                # 训练数据快照与标签导出
  runs/                     # 日志、配置、检查点与评估结果
  models/                   # 权重索引、模板、类别及环境信息
  backups/                  # 标注与配置恢复记录
  exports/                  # 用户主动导出的数据和模型
```

默认采用相对路径。若图片位于项目外，跨平台迁移向导提供“连同图片打包”或“重新定位目录”，不能把 Windows 盘符原样写进 Ubuntu 数据配置。大文件不做无节制自动重复备份；快照的图片复制、链接或引用策略按平台能力处理，并保证训练输入不被外部改动。

### 8.3 Windows / Ubuntu 支持边界

| 项目 | Windows | Ubuntu |
| --- | --- | --- |
| 首版目标系统 | Windows 10/11 64 位 | Ubuntu 22.04/24.04 LTS x86_64 |
| 交付形式 | 图形安装包或便携目录 | 优先独立应用目录/安装包，AppImage 作为打包评估项 |
| CPU 使用 | 必须验收 | 必须验收 |
| NVIDIA GPU 使用 | 通过驱动与 PyTorch 组合实测 | 通过驱动与 PyTorch 组合实测 |
| 路径 | 中文、空格、长路径场景 | 中文、空格、大小写敏感路径场景 |
| GUI 与进程 | 检查缩放、子进程启动与退出 | 检查 X11/Wayland、Qt 依赖与子进程退出 |

两边共享项目格式、骨点定义、快捷键语义和训练配方；运行环境分别构建，GPU 配置重新检测。初期优先复现 Windows 11 和 Ubuntu 22.04，再扩展其余目标系统。

采用应用专用运行环境，不自动修改系统 Python、已有 Conda 环境或其他项目依赖。新手首次启动只需要完成“检测设备 → 准备匹配运行时 → 运行自检”。联网下载展示大小、进度和失败重试；离线场景允许选择本地运行时及模型包。

## 11. 主要风险与处理方式

| 风险 | 处理方式 |
| --- | --- |
| EXE 对应源码和现有功能尚不明确 | M0 固定源码提交、核对本地版本，避免重复实现已有功能 |
| 多模型依赖互相冲突 | 适配器与版本锁定，必要时隔离运行时，提供实测矩阵 |
| GPU/驱动不兼容或显存不足 | 预检、短试跑、推荐小模型和小批量，失败后明确选择重试策略 |
| 自定义骨架与预训练任务不匹配 | 校验元数据，为目标骨架训练，不把通用人体模型当成万能骨点预测器 |
| 少量数据初始效果差 | 分场景取样、预览、补标、固定验证集；不承诺自动标注准确率 |
| 自动标注错误反复进入训练 | 审核准入、数据版本和来源追踪，保留高置信度随机抽查 |
| 两平台路径或依赖不同 | 相对路径、迁移向导、分平台构建与干净环境测试 |
| 项目与模型分发涉及许可 | 发布前核对固定源码、训练框架及权重的实际许可证，保留声明并按许可要求分发；不预设可闭源发布 |
