## 产品目标

做一个新手能打开、能理解下一步、能完整完成标注到训练迭代的本地桌面软件。骨点只是姿态任务的扩展，检测、实例分割、旋转框与分类同样是一等任务。原 X-AnyLabeling 功能继续保留，不用简化骨点演示代替完整软件。

## 界面方案

Electron 左侧依次为项目概览、数据与标注、标注工作区、训练中心、模型与预标注、人工审核、骨架设置。上方保留项目名和随时可切换的标注方式。概览强调三种流程及真实审核进度，空项目明确提示新建和导入。

深色基础色 #101216、侧栏 #14161B、卡片 #1B1E25、边框 #2C3039、正文 #ECEEF3、Amber #F0AD42。浅色使用 #F4F5F7 基底及白色卡片，强调色调整为 #BD7613。字体采用系统 Segoe UI / 微软雅黑，无需联网加载字体。保留键盘焦点、滚动导航和中文操作提示。

原生画布在 Windows 内嵌到 Electron 内容区，保留原菜单和工具。骨架/训练/审查的详细表单目前由原生窗口与扩展侧栏承载；不声称所有表单已经重写为 Web UI。

## 数据与接入架构

Electron 主进程负责生命周期、主题与白名单 IPC；渲染进程启用 contextIsolation、sandbox，不能直接使用 Node 文件系统或启动进程。Python QObject 通过队列信号在 GUI 线程执行命令，独立进程负责推理，训练复用原训练入口。Windows 通过原生父窗口句柄接入完整 Qt 工作区，退出仍经过未保存数据检查。

项目元数据使用原子 JSON 写入。导入图片使用副本，检测同名冲突。训练只取审核通过的数据并复制为独立快照；相同内容图片使用相同划分，追加数据保持既有划分。当前没有按来源视频、对象或场景分组，视频抽帧数据需人工规划独立验证集。

候选单独保存在 proposals/latest。接纳前核对正式标注哈希与任务/类别/模板，备份旧标注，再要求人工审核。自定义姿态权重需要与模板一致的元数据，防止骨点顺序错配。骨架预设不代表自带狗姿态模型。

## 后续执行顺序

1. Windows 与 Ubuntu 干净环境验收、依赖锁定和发行包；完成 Linux 单窗口方案验证，覆盖缩放、多显示器、关闭/恢复与长路径。
2. 增加完整数据分页、按视频/场景分组划分、模型运行历史与更直接的结果比较；避免用训练集指标代替泛化效果。
3. 增加狗姿态匹配模型接入验收、YOLO26 多任务验证、自定义模板版本迁移和更大数据集性能测试。
4. 优化新手流程：小规模真实项目可用性测试，明确选择模型、确认候选、审核和训练结果位置；再决定哪些详细原生表单适合迁移到 Electron。

验收原则：保留原版功能、保护已有数据、明确模型与模板匹配、操作有反馈；没有实测的能力不标成完成。
