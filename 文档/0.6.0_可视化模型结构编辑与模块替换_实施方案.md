# 0.6.0 可视化模型结构编辑与模块替换：实施方案

编写日期：2026-10-19。状态：下一版本建议方案，尚未实施或完成兼容性验证。版本号建议使用 0.6.0，实际发布号由发布时确定。

## 1. 目标与概念

在现有标注、训练、验证、转换工作流中增加“模型设计”工作区，让用户无需编写代码或 YAML，就能查看模型结构、修改受支持的结构参数、替换部分模块，并将设计保存为可复现的训练实验。

用户想法整合如下：

| 用户想法 | 产品功能 | 首版定位 |
| --- | --- | --- |
| 图形化修改模型参数 | 中文参数面板，区分训练参数与结构参数 | 必做 |
| 修改卷积核 | 在明确支持的普通 Conv 层修改核大小等参数 | 必做 |
| 修改“探头大小” | 暂解释为检测尺度、检测头输入特征和容量，界面使用准确名称 | 支持受验证模板 |
| 将一部分网络换成其他网络 | 在指定插槽替换为 Inception 风格模块 | 必做一个完整可用实现 |
| LeNet 换 GoogLeNet | 区分局部 Inception 模块替换与整套 GoogLeNet 主干替换 | 局部替换先做；完整主干后续做 |
| 图形化拼装网络 | 结构图、选中编辑、模板化增删与连接 | 首版固定连接，后续逐步开放 |

“linet/gogolnet”暂按 LeNet/GoogLeNet 理解。LeNet 与 GoogLeNet 原本主要面向分类，不能将分类输出直接接到检测头。本方案以其结构思想和可适配模块为目标，不承诺任意模型互换。

功能价值：学习结构、控制模型体积与计算量、验证小目标检测等改进假设。结构更复杂或卷积核更大不保证精度提高，所有效果结论以可比实验为依据。

## 3. 版本范围与优先级

### 3.1 0.6.0 必交付

1. 模型结构图：主干、特征融合、检测头分区；显示输入来源、有效通道数、步长、输出尺寸。
2. 基础模板：以当前锁定依赖自带的 YOLO11n 目标检测模型作为首个支持模板，先完成原结构无损往返。
3. 参数编辑：支持白名单 Conv 层的核大小、输出通道；支持选定模块的重复次数与模板级宽深缩放。
4. 局部替换：提供一个内置、可保存重载、可训练的 `InceptionBlockV1`，在经过验证的同尺度插槽中替换模块。
5. 检测尺度模板：标准 P3/P4/P5，以及候选 P2/P3/P4/P5 小目标模板；后者通过完整验收后才进入发布模板库。
6. 分级验证：配置检查、模型构建、前向推理、训练损失与反向传播、小规模真实训练。
7. 权重迁移报告、独立实验保存、接入现有训练/验证与项目模型选择。
8. 支持矩阵和中文错误提示；未知组合禁止启动训练。

首版结构编辑仅开放目标检测。现有分割、姿态、旋转框、分类继续使用原工作流，不因本功能开放未经测试的结构编辑。

### 3.2 后续阶段

- 0.6.x 候选：扩大局部模块库、补充已验证模型模板、改善对照实验展示。
- 0.7.0 候选：完整 GoogLeNet 或其他主干适配，输出可供检测使用的多尺度特征；再评估姿态与分割支持。
- 更后期：受类型约束的拖拽连线、用户模块开发接口、自动结构搜索。版本号仅作路线建议。

不把任意 `.pt` 反向转换为可编辑网络作为首版前提。任意本地权重可以保留现有使用方式；仅结构识别成功且命中模板的模型提供编辑入口，其他模型明确显示原因。

## 4. 用户操作与界面

新增侧栏“模型设计”，在训练页增加“设计模型 / 使用设计模型”。完整操作顺序：

1. 打开检测项目，选择“标准检测”“小目标检测”或“局部模块替换实验”。
2. 从内置模板创建副本，选择是否使用匹配的本地预训练权重。
3. 在结构图中点选层，在右侧查看中文说明、原值与修改值。
4. 修改参数或在支持插槽选择模块；图中同步高亮变更及显式新增的适配层。
5. 点击“检查结构”，查看通过项、失败位置、权重迁移和计算量报告。
6. 通过检查后“保存并去训练”，进入现有训练页，确认数据快照、设备和训练参数。
7. 完成后进入现有验证与预标注流程，和原模型对比；需要转换时按格式能力执行。

建议布局：左侧模板和模块列表，中间可缩放的结构图，右侧属性与兼容性说明，下方检查日志和变更列表。默认折叠底层细节，按模块显示；可展开查看内部卷积层。

两种显示模式：

- 简洁模式：选择目标和模板、有限档位、推荐参数，解释速度/体积/小目标的取舍。
- 专业模式：展示可编辑参数、源层连接、有效通道、结构差异和生成配置，只读查看 YAML 即可完成首版需求。

必须提供撤销/重做、恢复模板、新建设计副本、保存状态。检查任务可停止，失败保留设计和可读日志。切换项目时所有状态归属明确。

状态流程：`草稿 → 待检查 → 检查中 → 可训练 / 检查失败`。任何影响结构或目标输入尺寸的修改都使旧检查失效；训练状态引用不可变设计修订。

## 5. 参数和检测头的设计规则

| 参数 | 首版规则 | 说明 |
| --- | --- | --- |
| 普通卷积核 | 支持插槽可选 1/3/5/7，按层进一步收窄 | 不套用到全部卷积或模块内部 |
| 输出通道 | 在模板边界内设置，并满足模块约束 | 同时展示请求值与缩放、对齐后的实际值 |
| 重复次数 | 仅支持已适配的模块，限制在模板范围 | 区分模块内部重复与外部串联 |
| 宽深缩放 | 使用已验证档位，设置资源上限 | 层级覆盖与全局缩放的优先级必须固定 |
| stride / groups / dilation | 首版默认锁定，必要时由模板定义 | 避免破坏残差、分组整除和多尺度连接 |
| 检测尺度 | 切换整套模板 | 不允许单独增加一个未连接的输出头 |
| 类别数 | 从项目类别自动生成 | 不给用户填写与数据不一致的数值 |

结构编译的固定顺序：解析模板和缩放 → 计算有效通道/重复数 → 应用合法层级覆盖 → 校验所有连接 → 生成无歧义配置。若编译结果已展开有效值，导出的配置必须关闭二次缩放，防止加载后通道再次变化。

P2 模板应包含对应高分辨率特征、融合路径和最终检测输入。以 640×640、常见 stride 4/8/16/32 为例，P2/P3/P4/P5 特征图通常对应 160/80/40/20；实际值由真实前向传播确认。P2 增加计算和内存开销，小目标收益需要真实数据验证。

“检测头大小”在界面拆成“检测尺度”和“特征通道”，卷积核用“核大小”，避免把目标框尺寸、输入图片尺寸和结构尺度混为一谈。后处理阈值归入推理/验证设置。

## 6. 模块替换与 GoogLeNet 路线

### 6.1 首版：Inception 风格局部模块

采用标准卷积、激活和池化实现多分支特征提取：1×1 分支、降维后 3×3 分支、降维后较大感受野分支、池化后 1×1 分支，最后按通道拼接。具体分支比例和算子在实现时固定并版本化。

接口约定：输入 `[N,Cin,H,W]`，输出 `[N,Cout,H,W]`，首版不改变步长。分支通道分配必须是整数并满足总和为 Cout；保持空间大小一致，拼接维度固定。该模块借鉴 GoogLeNet 的 Inception 思想，不宣称等同完整 GoogLeNet 或可直接加载其全部权重。

先选定一个无跨越内部引用、输入输出契约清晰的插槽完成闭环。不得把带残差、注意力或内部重复的模块机械替换为任意分支模块。外部模块引用保持稳定 ID，由编译器重新生成数字索引。

### 6.2 后续：完整主干替换

GoogLeNet 主干适配器应移除分类器及训练辅助输出，明确各阶段输出、通道与步长；为检测网络提供需要的多尺度特征，并通过显式 1×1 卷积等适配后连接 Neck。单独定义预训练来源、许可证、离线资源和权重映射。

不将主干替换简化成下拉框改名。每个主干都需要独立的特征接口、构建、损失、保存重载、推理和导出验证。

## 7. 工程实现架构

### 7.1 核心数据与编译

使用有版本的 JSON 作为设计源文件，YAML 为编译产物。保存稳定节点 ID、模块类型、输入节点 ID、参数、模板版本与结构修订；界面位置单独保存，不参与模型语义哈希。

编译器负责拓扑排序、连接索引、通道与尺度推导、模板约束和配置生成。首版仅接受内置模块和注册表中的类型，不执行用户字符串代码，不为导入设计自动安装 Python 包。

模块注册表需描述：模块版本、参数 schema、输入输出契约、通道规则、重复方式、可替换插槽、支持任务和导出能力。首版不提供任意用户 Python 插件。

### 7.2 Ultralytics 集成的关键决策

先做小型技术验证，决定自定义模块的稳定接入方式。当前解析器对 `base_modules`、`repeat_modules` 及特殊模块分别处理，单纯把类放入全局名字空间不够。

优先尝试将 Inception 块编译为当前解析器支持的基础算子图；保留稳定节点 ID 与源码映射。若无法可靠表达，则在项目内维护针对锁定 Ultralytics 版本的最小构建适配器，为注册模块明确传递 Cin/Cout 和重复规则，并验证检测任务初始化、损失与 Trainer 的重新构建行为。

不直接手改 `.venv/site-packages` 作为交付方式，不依赖只在一次进程中有效的临时对象替换。若确需供应商补丁，必须纳入源码、版本锁、双平台打包和升级回归，记录补丁差异。

Go/No-Go：只有“编辑 → 构建 → Trainer 内部构建 → 训练 → 新进程重载 → 验证”都能复现一致结构，才进入界面功能开发。

## 8. 权重迁移与训练接入

流程：先按设计创建目标结构，再显式加载匹配的源权重，再启动训练。结构配置与预训练权重分别记录，避免只传 YAML 导致用户误以为已加载预训练权重。

迁移采用节点来源映射、模块语义及张量形状共同判断，不能只凭相同形状或变动后的数字层号复制。新模块与不兼容层重新初始化；不自动裁切/填充卷积核来伪造完整迁移。

报告至少列出：源权重 SHA256、成功张量数、匹配的可训练参数元素数 / 目标可训练参数元素总数、缓冲区单独统计、跳过层及原因、随机初始化层。明确覆盖率不代表保留同等能力。

修改结构后禁止沿用原优化器状态进行断点续训。只有结构、任务、数据等恢复条件兼容时才允许原结构续训；新结构作为新实验。部分迁移或从零训练在界面显式显示。

接入现有数据冻结流程，同时冻结结构、初始化方式和训练参数。基础模型与改进模型可以引用同一个数据快照，不得各自重新划分后直接比较。

## 9. 保存与可追溯性

项目下建议布局：

```text
model_designs/<design-id>/
  design.json                      # 名称、当前修订、设计身份
  revisions/<revision-id>/
    graph.json                     # 不可变结构与模板来源
    model.yaml                     # 编译配置
    manifest.json                  # 语义哈希、依赖、任务、模块版本
    checks/<check-id>/report.json   # 检查输入、状态与结果
    checks/<check-id>/check.log
runs/<existing-run-name>/
  design_snapshot/                  # 本次结构、检查与初始化报告
  experiment.json                 # 数据快照哈希、种子、参数、环境
  ...                             # 继续使用现有训练输出
```

设计修订只新增，不覆盖训练引用版本。文件原子写入；失败检查独立留档。现有模型和标注数据不迁移、不覆盖。移动项目后通过相对路径与哈希定位资源，外部权重可以选择复制进项目并校验。

修改 YAML、模块版本、任务或有效输入配置后，重新计算哈希并使相关检查失效。已有检查不能作为后来结构的训练凭证。

## 10. 自动检查、资源限制与错误提示

| 等级 | 检查内容 | 通过后能说明什么 |
| --- | --- | --- |
| L0 配置 | schema、白名单、范围、无环、引用、任务、版本 | 配置符合规则 |
| L1 构建 | 通道、整除、残差、分支尺寸、索引、检测输入 | 网络能构建 |
| L2 前向 | eval 模式，在所选输入尺寸进行模拟输入推理，检查输出和有限数值 | 推理路径能执行 |
| L3 梯度 | train 模式，用合法检测标签计算真实任务损失并反向传播，检查有限值和预期梯度 | 训练路径基本可执行 |
| L4 短训 | 小型真实已审核数据，完成优化步骤并保存、新进程重载、验证 | 本组合完成最小训练闭环 |
| L5 发布 | 双平台安装包、真实界面、模型全流程及声明的导出格式 | 达到本版本交付标准 |

真实训练启动前至少通过当前修订的 L0–L3；模板进入内置发布库需通过 L4–L5 的对应平台/能力检查。真实短训不会被模拟张量检查替代。

检查在独立进程执行，有超时、取消和主进程退出清理。默认 CPU 和受限批大小；训练前按目标设备及输入再做资源预检。参数量精确统计，MACs/FLOPs 明确统计口径和输入尺寸；不支持的算子显示“估算不完整”。显存估算标为参考，实际峰值另记，不能保证不会 OOM。

错误信息定位到可见节点，例如：“融合层 N17 的两个输入分别为 80×80 和 40×40，无法按通道拼接。请恢复该层步长或选择匹配模板。”后台堆栈保存在日志，界面给出可操作原因。

## 11. 实验对比与模型转换

对比表包含：设计修订、数据快照、初始权重与迁移率、训练配置与种子、mAP50-95、precision、recall、参数量、计算量口径、权重体积、推理耗时和测量环境。

- 原始模型和改进模型使用同一数据快照、类别、输入尺寸与主要训练预算；初始化方式不同需明确标记。
- 默认以现有验证集做开发对比，当前没有独立测试集时直接显示“无独立测试集”。后续保留的测试集只用于最终评价。
- 速度比较使用相同设备、精度、批大小、预热与计时范围；分别记录纯模型耗时和端到端耗时。
- 单次小数据实验只能证明该次结果；需要效果结论时增加多随机种子或更充分实验。不得预写“提升百分比”。

自定义模块首选标准可导出算子，但每种格式仍需实测。首版至少打通一个自定义模型的 ONNX FP32 导出与 ONNX Runtime 数值/检测结果对比；FP16、INT8、TorchScript 各自维护能力状态。INT8 继续使用代表性真实校准图片，并单独评估任务精度。未验证格式在该模型上禁用并说明原因。

## 12. 开发顺序与阶段交付

| 阶段 | 工作 | 可检查交付与进入下一阶段的条件 |
| --- | --- | --- |
| M0 基线与备份 | 备份拟修改文件、依赖锁定、模板与版本记录；校验 SHA256 和恢复清单 | 备份可恢复，原训练流程基线明确 |
| M1 技术验证 | YOLO11n 无损重建；一个 Inception 插槽；统一加载器原型 | 原结构往返一致；自定义模型真实短训、新进程重载和验证通过 |
| M2 结构核心 | JSON schema、编译器、修订、权重映射、L0–L3 | 合法结构能运行，非法结构有可定位错误，报告可信 |
| M3 图形界面 | 模板、图、参数、替换、撤销、检查状态 | 用户无需代码完成结构修改与保存 |
| M4 工作流闭环 | 训练、验证、预标注、视频、转换、对比记录 | 所有声明支持的入口能加载同一修订与权重 |
| M5 P2 与发布 | P2 候选验收、双平台安装包、离线与移动路径 | 支持矩阵逐项有证据，发布说明与实测一致 |

M1 是最大技术风险，应先完成再确定工期。粗估单人投入约 4–7 个有效开发周：技术验证 3–5 天，核心 5–8 天，界面 4–6 天，工作流和实验 4–6 天，双平台验收 4–7 天；属于排期参考，不是完成承诺。自定义解析和打包出现问题时重新评估，不压缩验收冒充完成。

## 13. 验收标准

1. 原 YOLO11n 模板导入、保存、重载后有效结构、参数量及固定权重下输出一致；显示与实际构建一致。
2. 受支持卷积核和通道修改真实改变网络；超范围、残差冲突、分支尺寸冲突被拒绝；缩放不重复应用。
3. 一个 Inception 局部替换模型完成 L0–L4，保存后退出程序，新进程能加载并推理。
4. 权重报告能区分复制、跳过和随机初始化，索引变化后不发生静默错配；结构修改禁止错误续训。
5. P2 模板若发布，检测实际使用四个预期尺度并完成短训；若未通过，产品不可选择该模板，发布说明明确延期。
6. 从界面创建、编辑、撤销、保存、检查、训练、验证、预标注与查看历史均完成真实 Electron 操作验收。
7. 模型转换至少通过声明支持的 ONNX FP32 流程和结果一致性检查；其他格式逐项标记。
8. Windows 与 Ubuntu 均验证安装后的模块发现、中文/空格路径、项目移动、停止检查、失败恢复和原功能回归；WSLg 结果不能代替标准 Ubuntu 桌面验收。
9. CPU 必验；CUDA 在具备设备的平台验证并记录型号、驱动和运行库。没有设备的项目标记“未验证”，不写成支持已验收。
10. 不覆盖原权重、正式标注和原设计修订；AI 候选继续经过人工审核后进入训练。

测试重点是结构编译、权重映射、保存重载与任务集成等真实故障边界。JavaScript/Python 单元测试不能替代桌面、训练和安装包验收。

## 14. 主要风险与处置

| 风险 | 处置 |
| --- | --- |
| Ultralytics 升级改变解析/Trainer 行为 | 锁版本，适配器集中维护，升级执行模型往返与训练回归 |
| 训练可用但其他进程找不到自定义类 | 所有入口使用统一加载器，稳定导入路径，安装包新进程验收 |
| 修改结构后误加载权重 | 稳定节点来源映射、语义与形状联合检查、显式迁移报告 |
| 通道和重复缩放导致界面与实际不一致 | 展示最终有效值，编译一次，构建结果反查 |
| P2/大卷积引起显存或耗时增长 | 模板范围、独立资源预检、停止机制、实测峰值 |
| 模型能跑但精度下降 | 固定数据快照与基线对照，保留原始模型，无预设提升承诺 |
| 完整主干替换拖延整个版本 | 作为后续独立能力，0.6.0 保证局部模块替换闭环 |
| 发布包漏带模块或路径只在开发机有效 | 双平台安装包、离线和移动路径验证，不能仅跑源码 |

## 15. 建议冻结的产品决策

建议下一版本按“模型设计工作区 + YOLO11n 检测模板 + 普通卷积编辑 + 一个 Inception 局部替换 + 分级验证 + 训练验证闭环”启动开发；P2 为需验收才能开放的候选模板。

完整 GoogLeNet 主干、更广泛模型族和自由拖拽连接保留为明确后续阶段。首版交付标准是用户可以可靠地改出一个可复现、可训练、可重新加载并能比较结果的模型。

本文件只新增方案文档，不修改软件功能、依赖、版本号或发布资产。下一步最先执行 M0 与 M1，再依据技术验证结果细化工期和支持矩阵。
