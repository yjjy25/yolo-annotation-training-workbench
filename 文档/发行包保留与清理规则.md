# 发行包保留与清理规则

自 2026-10-20 起，按用户要求，发行包只保留最新一个已验证正式版本。

1. 先生成新版本 Windows EXE、Ubuntu DEB、对应源码包及校验清单；逐一核对大小和 SHA256。
2. 若本次发布到 GitHub，须确认正式 Release 已发布、附件完整可下载，才清理本机旧版本。构建失败或发布未完成时保留上一版。
3. 正式发行目录只留最新版本安装包、源码及其 GitHub 分卷；旧源码和历史 Git 资料先归档到“备份”，不直接丢弃。
4. 发布完成后，移除不再使用的 staging 目录、安装验证解压副本和可重新下载的构建缓存。删除前归档其中的可变配置、验收记录和可能存在的工作台数据，并排除运行中的进程。
5. 每次生成当次明确路径清单并校验边界；不得按通配符对整个项目执行递归清理，不得沿符号链接或目录联接删除目标。
6. 保留工作目录的源码、用户项目、原始模型、已有备份、当前 .venv、.runtime、desktop/node_modules 和 Linux 基础构建环境。
7. 清理后验证保留文件的哈希、开发启动环境和剩余安装包，并记录磁盘空闲空间变化。硬链接路径大小不等于实际释放量。

本次执行清单和备份位置记录在 `.packaging/cleanup-latest-plan-path.txt` 所指向的 JSON 文件中。
这是发布时的整理规则；不会在后台定时删除文件。
