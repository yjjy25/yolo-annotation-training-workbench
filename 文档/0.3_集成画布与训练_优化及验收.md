# 0.3 集成画布与训练：优化及验收

日期：2026-10-16。本文替代 0.2 中“嵌入原生窗口作为主画布”的实施方案。

更新：0.3.1 已将原版高级工具也接入同一个 Electron 窗口，并完成退出修复。本文关于“独立补充窗口”的描述属于历史方案，以 [0.3.1 验收记录](0.3.1_内嵌工具与退出修复_验收.md) 和根目录 README 为准。

## 本次问题与修复

| 用户问题 | 修复 |
| --- | --- |
| 一直显示连接原生工作区 | 主标注画布改为 Electron 内的 Canvas 编辑器，项目和训练表单也直接内置；不再依靠跨进程窗口嵌入来显示主功能。原生工具继续作为补充入口保留。 |
| 字体看不清 | Electron 深浅表单均显式设置输入背景、前景和焦点；修复旧扩展样式中的字面 white 未跟随主题问题。原生新建表单也验证了文字对比度。 |
| 类别不能切换 | 区分任务类型与对象类别；新建项目用五个任务按钮选择，画布右侧下拉切换类别，“＋”追加类别，数字键 1–9 快选，并支持修改选中对象的类别。追加类别保留既有序号与标注文件。 |
| 骨架入口突出、标注单一 | 取消侧栏独立骨架入口，仅姿态任务显示模板和点位操作。检测、分割、姿态、OBB、分类各有适用工具。 |
| 标注后训练不明确 | 新增内置模型训练页：审核数量、初始模型、CPU/GPU、参数、开始/停止、真实日志、结果目录、模型列表以及“用于预标注”。 |

窗口接入的旧验证只检查了父窗口与尺寸，没有覆盖 Chromium 和 Qt 的实际合成显示，不能据此认定用户看到画布。本版通过真实鼠标/键盘编辑、文件保存与训练过程验证，不再使用这些句柄检查作为主画布可用的依据。

## 界面与交互

继续参考 Kudu 的桌面结构和 Amber 强调色，以及 Ultralytics 以数据集为中心的标注流程；不依赖 Kudu 运行时，不嵌入网站，不要求登录或上传数据。

主导航简化为数据与标注、标注画布、模型预标注、人工审查、模型训练。工作区采用“左侧缩略图—中央画布—右侧类别和对象”的布局。新建项目直接在工具内完成，任务按钮附带工具说明；骨点配置只在姿态任务中出现。

深色文字 #F0F2F6、输入底色 #252932、次要文字 #B0B7C4、Amber #F1B34C；浅色文字 #192433、输入底色 #F6F8FB。字体使用 Segoe UI / 微软雅黑，保留明确焦点、禁用状态与滚动范围。

| 任务 | 内置操作 |
| --- | --- |
| 检测 | 拖动画框、拖动与角点缩放、修改类别 |
| 实例分割 | 点选多边形、Enter/双击完成、顶点微调、整体移动 |
| 姿态 | 人17/狗24/自定义模板，框内模板放置或顺序点选，遮挡、跳过、单点与整组移动 |
| 旋转框 | 拖动画初始框，选择后拖动旋转手柄，角点缩放 |
| 分类 | 应用当前整图类别或数字键选择 |

通用操作包括缩放、适应画布、中键平移、撤销/重做、删除、保存、审核后下一张、候选叠加和接纳。离开页面或切图前保存修改；保存失败保留画布，不静默丢弃。多边形未完成时要求完成或取消。

## 训练与迭代

1. 标注并审核数据。至少两张内容不同的已审核图片才能建立训练/验证划分；实际任务需要更多真实代表性数据。
2. 在模型训练页选择对应任务的模型或本地权重，配置设备和参数。
3. 训练使用冻结的数据快照，由 X-AnyLabeling 原 Ultralytics worker 在独立进程运行。
4. 训练日志与权重保存在项目 runs 中，界面显示真实状态，不用模拟进度代替完成。
5. 在已训练模型中点击“用于预标注”，生成全部图片候选；接纳、微调并重新审核，再进入下一轮训练。

修复了浏览器数字输入步长导致默认学习率/置信度无法提交，以及跨任务切换时继承不适用默认模型的问题。停止训练只终止本工具创建的训练进程；并发训练/预标注会明确阻止，避免误开重复任务。

候选独立存储，接纳前检查原标注哈希并备份。正式标注保存也检查基准哈希，防止原版补充窗口或其他工具的修改被覆盖。姿态自训权重带有模板匹配元数据。狗24是既有 Dog-Pose 数据集的顺序，不等于网站中其他狗骨架模板或现成人体模型。

## 验证结果

- Python workflow 回归 24 项通过：五任务保存/审核/哈希冲突、追加类别不改旧标签、非法坐标与越界路径、主题文字对比度、新建任务按钮和骨点显隐、关闭补充窗口保留主引擎，以及此前的数据快照和原动作/快捷键测试。
- 真实 Electron 鼠标/键盘验收：新建五种任务、类别追加与切换、各任务画布标注和保存。人体姿态保存框加17个点，分类保存整图类别。记录 `.runtime/studio-check.json`。
- 从内置训练页实际完成一次 CPU 短训练，生成 best.pt；日志记录真实训练输出。仅使用合成流程测试图，不代表真实任务精度。
- 额外交互验收：选择对象不使标注变脏、拖动保存后重开、旋转框旋转、分割顶点微调、姿态整组移动、顺序点选与跳点、训练模型为6张图生成候选且正式标注不变、接纳候选、模式切换保护、打开完整原版工具。记录 `.runtime/studio-extra-check.json`。
- JavaScript 语法检查通过；实际渲染未报告控制台错误。新建表单深浅截图与五任务画布截图位于 `界面预览/Studio-*.png`。

此前的原 worker 五任务 CPU、v8/11 GPU 短训练与 ONNX 验证仍保留在早期验证记录中。本轮新训练页实测的是 CPU 路径，不把此前结果表述为本轮所有设备/型号组合均已重新验证。

## 当前范围与后续

每个项目对应一种训练任务；不会把已有标注直接转换成其他任务。自定义模板在创建时可填写名称、顺序、连线与对称；已有标注的模板迁移仍未实现。原版补充工具使用独立窗口，其全部模型配置、导出格式和额外推理后端仍须各自的权重与依赖。

Ubuntu 已提供启动和环境准备脚本，尚未实机验收。干净电脑便携打包、大数据量、多屏缩放、更多模型组合和真实数据精度仍是后续验收目标。
