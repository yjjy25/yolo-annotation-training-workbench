# 0.4 多实例、多类别与双平台发行验收

日期：2026-10-16。版本：0.4.0。扩展基于官方 X-AnyLabeling 4.1.3，源码基线 `745f6c355f94cddb06f6965b3a4118f82033e935`。

## 用户要求与实现

| 要求 | 当前实现 |
| --- | --- |
| 一张图有多个检测类别 | 每个目标框、分割轮廓或旋转框分别保存自己的类别，右侧按钮、下拉框和数字键切换类别 |
| 同一张图有多种姿态 | 每个姿态实例有独立类别、框、骨点和 `group_id`；例如两个对象分别标“站立”和“趴卧” |
| 姿态仅作为扩展 | 保留检测、分割、姿态、旋转框和分类；仅姿态项目显示人17、狗24或自定义骨点选项 |
| 三种标注方式切换 | 人工、已有模型批量候选、少量人工标注后训练再批量候选；候选均需人工审查 |
| 集成训练 | 已确认数据生成独立训练快照，CPU/GPU 实际训练，生成 `best.pt` 后继续用于预标注 |
| 便捷美观 | Electron 自定义标题栏、侧边工作流、Amber 强调色及浅色/深色/系统主题；只参考 Kudu 设计，不依赖其运行时 |
| Windows 和 Ubuntu 下载 | Windows x64 离线解压安装 EXE；Ubuntu amd64 DEB；均包含独立运行环境和 CPU/CUDA 依赖 |
| 保留原工具 | 原 EXE 保留；完整上游源码随包。高级二维工具通过 Qt 离屏画面和输入转发显示在 Electron 内 |

“多个标签”按用户澄清实现为同图多个对象、多个类别及姿态实例。图片分类仍为单一整图类别。姿态项目内所有类别共享同一骨点定义与顺序；不同定义分别建项目。

## 本轮修复

- 类别按钮切换后直接进入对应绘制模式；已有对象可明确执行改类操作。
- 姿态骨点与骨线跟随所属对象的类别颜色，减少多实例混淆。
- 用 SVG 图标替代缺字字符；随包提供 Noto Sans SC 及 OFL 许可，改善 Ubuntu 中文显示。
- 鼠标释放时更新最终坐标，防止快速拖动最后一次移动事件缺失导致框的终点偏移；发行自动检查比较保存坐标和实际释放位置。
- 默认训练和预标注优先读取随包权重；绘图字体写入框架实际使用的配置目录，避免等待字体下载。
- 训练图表显式注册中文字体。简洁训练页使用 SGD，使填写的初始学习率实际生效；AMP 默认关闭，开启后框架可能首次下载检查模型。
- 开发版、Windows 便携目录、Ubuntu 用户数据位置分别计算；程序安装位置不作为 Ubuntu 项目存储位置。
- Windows ZIP64 自解压包检查输出路径；DEB 记录正确的 Unix 符号链接、可执行权限及 `chrome-sandbox` root:root/4755。

## 实际验证与证据

自动界面验收各使用 6 张 64×64 合成图片。其中 2 张标注并确认用于训练/验证，随后训练 1 轮，再对全部 6 张图生成候选。检测项目每张有“猫/狗”两个框；姿态项目每张有“站立/趴卧”两个独立狗24实例、共48骨点。检查 `best.pt` 存在、6份候选齐全，且正式标签哈希不变。

## 验证边界

- Ubuntu 的实际运行环境是现有 WSL Ubuntu 26.04.1/WSLg。DEB 目标为 Ubuntu 22.04+ amd64，尚未在用户双启动 Ubuntu 22.04 实机完成安装和运行验收。
- WSLg 自动界面验证使用 `--no-sandbox --disable-gpu` 启动 Electron；PyTorch 使用 GPU 独立验证。正式 DEB 的应用入口不含这两个参数，正常桌面沙箱启动仍待实机验证。
- WSLg 测试所需的系统图形库通过下载解包到项目内提供，没有执行 apt 系统安装；DEB 安装时由依赖声明交给 apt 处理。
- 合成图片只证明数据、编辑、训练和推理流程连通，不代表真实识别精度。真实任务需更多多样数据和独立测试集。
- 原版菜单和源码保留，常规二维操作已接入。所有高级推理模型、交互分割后端、OpenGL/点云、导出格式及 YOLO 型号尚未逐项验证，可能还需相应依赖与权重。
- 发行包未数字签名。附带模型之外的其他模型，以及主动启用 AMP 的检查模型，首次使用仍可能联网。
- 退出恢复材料已保留，但恢复冲突和未完成轮廓尚无一键恢复界面。
