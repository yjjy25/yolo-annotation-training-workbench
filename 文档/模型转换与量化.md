# 模型转换与量化

本次功能已加入工作区源码，尚未重新生成安装包。重新运行根目录的“双击启动.vbs”后，进入侧栏“模型转换与量化”。也可以在“模型训练”的已训练模型列表点击“转换 / 量化”。

1. 打开或新建一个项目，选择本项目训练权重或本地 YOLO `.pt` 文件。也可以不打开项目：直接点“选择本地 PT 权重”选自己的 `.pt` 就能转换，结果写入工作台数据的 `exports`。
2. 选择 ONNX 或 TorchScript，再选择精度与图片尺寸。TorchScript 当前只提供 FP32；尺寸必须为 32 的倍数。
3. ONNX INT8 需要校准图片文件夹，支持子文件夹，无需标注。默认最多使用按路径排序的前 100 张图片。建议准备至少 100 张覆盖真实部署场景的训练图片，避免使用最终测试集。少量图片仅适合测试流程。
4. 点击“开始转换”，查看运行状态与日志。可以停止，运行中不能切换项目或启动训练、预标注、验证。
5. 点击“打开输出目录”。每次输出位于 `exports/<时间戳-唯一标识>/`，包括模型、`export.json` 和 `export.log`。打开项目时 `exports` 在项目内；未打开项目时在工作台数据目录。原始权重不会覆盖。失败或停止目录可能留有未完成文件，应依据记录状态判断，不能直接部署。

| 目标 | 精度 | 转换与检查 |
| --- | --- | --- |
| ONNX | FP32 | CPU 导出、ONNX 结构检查、一次 CPU 推理 |
| ONNX | FP16 | FP32 导出后转换内部算子，保留 FP32 输入输出、重新排序节点、结构检查 |
| ONNX | INT8 | 代表性图片静态 QDQ 校准，Conv / MatMul / Gemm 量化，逐通道权重，结构检查与一次 CPU 推理 |
| TorchScript | FP32 | 保留 Ultralytics 元数据、重新加载并进行一次 CPU 推理 |

固定输入为 `1 × 3 × imgsz × imgsz`。检测、分割、姿态和旋转框采用 RGB、按比例缩放补边、除以 255；分类使用 Ultralytics 分类预处理。实际输出结构与后处理取决于模型任务及版本。当前不包含 TensorRT / OpenVINO 导出，也没有把部署格式接入现有 PT 模型验证页面。

FP16 需要目标推理引擎支持半精度算子。INT8 不保证加速或保持任务精度；必须在目标设备和真实验证集重新测量。缺失 ONNX 依赖会明确报错，工作台不会自动安装依赖。

MaixCAM / Pro 模式支持 YOLOv5u、YOLOv8、YOLO11、YOLO26 四种检测权重，家族按实际网络层识别；每种家族检查的结构、导出参数与实测结果见 [MaixCAM导出模式.md](MaixCAM导出模式.md)。

## 转换自己的权重（不依赖本项目）

- 训练完的模型有三个入口：训练页状态区的“转换这个模型”（本次训练完成时）/“转换最新模型”，训练页“已训练模型”每行的“转换 / 量化”，以及“项目模型管理”每行的“转换”（包含项目 `models` 里导入的 PT）。点完会带着该权重直接进入本页并选中。
- 本页下拉框列出本项目训练出的 `best.pt`，标签是“训练 11-07 03:15 · 本项目模型”，最新训练在最前并默认选中；选中后“当前模型”显示路径尾部、存储精度与格式，便于确认没选错。
- 点“选择本地 PT 权重”可选任意位置的 `.pt`。不打开项目也能用：点同一个按钮选文件后，“开始转换”即可用。
- 输出位置跟着当前状态走：打开项目时在项目 `exports/<时间戳-唯一标识>/`，未打开项目时在工作台数据目录的 `exports/`（打包版在“工作台数据”，源码运行在 `.runtime`）。`export.json` 额外记录 `scope`（`project` / `workspace`）与本次 `root`，便于区分来源。
- “打开输出目录”优先打开页面上这次转换的目录；没有记录时打开当前项目（或工作台）的 `exports`。
- 只转换 Ultralytics 可加载的 YOLO `.pt`。YOLOv5、其他框架或纯 `state_dict` 的权重无法在此直接转换，现在会明确提示先转成 Ultralytics 格式；`.pt` 以外的文件不接受。
- 只列出 `best.pt`；要转 `last.pt` 请用“选择本地 PT 权重”打开该文件。
- 转换使用源文件的私有副本，源权重 SHA256 与修改前一致才会记为完成。
