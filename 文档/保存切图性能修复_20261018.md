# 保存切图黑屏与等待修复

2026-10-18，源码修改，未重新构建或发布安装包。

## 原因和调整

在用户钢球视频的 79 张 720×1280 标注帧副本上复现：每次保存审核都会重建左侧 22 个缩略图元素，导致整列图片同时重新解码；主进程还会重复读取、解码原图并转成 PNG。审核同时等待数据集图片列表刷新，加重了等待。

- 原图 JPEG/PNG 保留原压缩字节，异步读取并缓存；缩略图优先使用异步系统缩略图接口，按路径、文件大小、修改时间和宽度区分缓存。
- 限制缩略图工作并发，优先原图读取；原图缓存与缩略图缓存共享有界容量。编辑器最多预读缓存 4 张解码图片。
- 普通图片与视频待微调缩略图按名称复用 DOM，只增删变化的条目，保持已解码图片。
- 视频待微调总览内容没有变化时保留原卡片，避免后台同步重新解码图片或打断按钮点击。
- 视频帧在后端成功审核后立即从待微调队列移除并自动下一张，350ms 后同步统计和视频清单；进入数据集页面会重新加载列表。后台同步不替代实际审核成功。
- 画布尺寸没有变化时不重置绘图缓冲区。保存或下一张加载失败时继续保留可用画面。

## 实机结果

Electron 原生窗口中使用真实尺寸图片副本，按 S 连续保存审核五次，对比修改前后。原项目文件和标注未用于写入测试。

| 指标 | 修改前 | 修改后 |
| --- | --- | --- |
| 保存并切到下一张中位耗时 | 1491 ms | 81 ms |
| 五次耗时 | 1278 / 1252 / 1552 / 1491 / 1496 ms | 86 / 71 / 84 / 81 / 75 ms |
| 每次缩略图全空白的动画采样帧 | 58–62 | 0 |
| 每次保留原缩略图元素 | 0 / 22 | 21 / 22 |
| 画布图像像素采样变黑 | 0 | 0 |

本次明确复现的是左侧缩略图整列变黑；修改前的同组测试中，中央画布未采到全黑画面。上述耗时是本机副本测试结果，不保证所有设备、格式和超大图片相同。

验证材料：`.runtime/image-refresh-before/report.json`、`.runtime/image-refresh-final/report.json` 和对应窗口截图。首次优化验证的中位耗时为 100ms，最终源码复验为 81ms。保存流程原生回归的 13 项检查覆盖普通数据集、视频待微调、过滤分页、连续按键、失败重试和最后一张保留画面，最终通过记录位于 `.runtime/save-advance-image-refresh-verified/report.json`。中间一轮在最后一帧总览切换处超时，随后增加诊断并保留无变化的总览卡片，最终完整通过。Node 回归覆盖图片缓存的并发复用、压缩格式保留、修改时间失效、跨项目隔离、失败重试、容量限制，以及现有编辑器交互。

修改前备份为 `备份/20261018-224651-image-refresh-stall`，含逐文件 SHA256 清单。使用项目源码启动脚本重启后加载本次修复；0.4.1 安装包未包含这些修改。
