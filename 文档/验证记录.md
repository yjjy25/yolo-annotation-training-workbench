## 高 DPI 与主题修复（2026-10-16 追加）

本机为 200% 缩放显示（devicePixelRatio 2）。此前“浅色/深色切不动”“进高级标注画面一下大一下小、糊得没法用”由三处独立缺陷叠加造成，均已修复：

| 现象 | 原因 | 修复 |
| --- | --- | --- |
| 高级标注画面反复忽大忽小 | 布局把逻辑像素乘了显示缩放后再发给 Qt，200% 下工作区窗口被请求成 2 倍尺寸并撞上 1800×1200 上限，截图帧与面板尺寸不再一致 | `main.cjs` 只发逻辑像素；Qt 保留布局尺度，另用 `scale` 字段只提升位图分辨率 |
| 高级标注整体发虚 | offscreen Qt 平台固定报告 dpr=1，截图只有 1 倍像素，Electron 再拉伸到 2 倍区域 | 按宿主显示缩放合成帧，帧像素 = 逻辑尺寸 × 缩放；Qt 内容在 200% 下为原生分辨率 |
| 深色下高级标注仍是大白面板 | 首次切换主题时只登记了控件原始样式，没有在当次重着色，控件被永久冻结在旧主题 | 登记与重着色在同一次遍历内完成；浅色时按登记值还原 |
| 切回浅色后 Qt 控件仍是深色 | 只有 `get_dark_palette()`，浅色回退到 `standardPalette()`，回不到应用原有调色板 | 记录应用初始调色板并在浅色时恢复；深色统一切到 Fusion 调色板 |
| 画布上的“画布显示”浮层在深色下刺眼 | 该浮层自带写死的浅色卡片样式，不参与主题重着色 | 新增 `CanvasAdjustmentWidget.apply_theme()`，随主题刷新卡片、文字与滑槽 |
| 主题选择重启后丢失 | 偏好写入目录不存在时 `writeFileSync` 抛错被静默吞掉 | 写入前 `mkdirSync(recursive)`，失败写日志 |
| 图库缩略图发虚 | 固定生成 200×150，200% 下被拉伸约 3 倍 | 按渲染进程上报的 dpr 生成 300×200 逻辑像素的位图（quality: best） |
| 浅色下辅助文字偏淡 | `--muted` 在浅色底上对比度约 4.6:1，状态标签更低 | 重设浅色中性色，关键辅助文字对比度提升到 7:1 以上 |
| 直接点“高级标注”得到空白工具面板 | 进入画布/高级标注时没有先加载图片列表，`editor.name` 为空，原版工具打开时没有图片 | 进入画布或高级标注前先 `loadImages()`，未选图时自动打开第一张；`editor.name` 为空时把列表首张传给高级面板 |
| 没有项目就点“高级标注”得到空壳 | 缺少项目前的入口校验 | 无项目时提示“请先新建或打开项目”并打开新建向导 |

## 深色模式“点一下又弹回浅色”的真因（2026-10-16）

这是本轮唯一确认为代码缺陷的问题，已定位并修复：

```js
// 修复前
document.querySelectorAll('[data-theme]').forEach(b=>b.onclick=()=>api.theme(b.dataset.theme));
```

`<html>` 元素本身也带 `data-theme` 属性（由 `update()` 写入），所以这个选择器把**根元素**也选中了，于是整个页面被挂上了“点击即切换主题”的处理器。用户点“深色”后：主进程写盘为 dark、界面变深色，随后**任何一次点击**（包括这次点击在捕获/冒泡阶段的其它处理）都会再触发一次 `api.theme('dark')`；而 `document` 级处理器与按钮处理器的触发顺序、加上 `update()` 每秒重发状态，最终表现为“按下深色后瞬间换回浅色”。

修复内容：
1. 选择器改为 `button[data-theme]`，只绑定三个主题按钮，根元素不再有处理器；
2. 移除顶栏重复的主题切换（按反馈只保留左下角那一组，并上移到引擎状态之上，短窗口也不会被裁掉）；
3. 新增点击级回归：真实鼠标点击“深色”后连续采样 6 秒，主题恒为 dark；随后点击页面其它位置，主题保持不变；点“浅色”再离开，同样稳定。实测 `document.documentElement.onclick === null`，选择器只匹配到 `light/dark/system` 三个按钮。

## 多边形“画出来了却无法保存”的根因（2026-10-16）

用户反馈：多边形已经画出来（画布上有轮廓），点“确认无误，下一张”却弹出“图片没有目标，确认作为负样本审核通过？”，也就是保存时 `editor.data.shapes` 是空的。

分步探针复现到的真实经过：

1. 逐点点选时点只进 `pending`（正在勾画的临时轮廓），**尚未**进入 `data.shapes`；
2. 我上一轮为“安全网”写的 `render()` 兜底逻辑会在每次重绘时，把 `pending` 里不足 3 点的内容清掉（原意是防止脏数据），结果**每次点击后的重绘都把刚加的点丢了**，所以三点永远凑不齐、轮廓永远无法闭合；
3. 画布上仍画着那条虚线轮廓，于是用户看到“已经画好了”，但数据里是空的。

修复：

| 位置 | 改动 |
| --- | --- |
| `down()` 多边形分支 | 攒够 3 个点立即提交为多边形（`finishPolygon()`），不必再去点“完成轮廓” |
| `render()` 兜底 | 只在保存过程中（`finalizing` 标志）生效，绘制期间绝不改动 `pending`；且兜底是**提交**而不是丢弃 |
| `grabbed` 顶点吸附 | 正在勾画轮廓时不参与吸附，否则新点会抓住上一个点、把轮廓打断 |
| `finishPolygon()` | 2 个点转成矩形、1 个点保留并提示，不再静默失败 |
| `save()` | 保存前先 `closePendingContour()`；2 个点自动成框，1 个点给出明确提示 |
| `approve()` | 先尝试闭合轮廓，再判断是否真的“无目标”，文案也改成更清楚的说明 |
| 「完成轮廓」按钮 | 有未闭合轮廓时常驻显示并带点数：`完成轮廓（3 点）` |

本机实测：3 次点击 → 生成 1 个多边形 → 保存 → 落盘 `disk=1`；`A3` 两点自动成矩形（`disk=2`）；单点残留时给出提示且不写入非法形状；连续画 3 个多边形后保存落盘 `disk=3`。形状回归（矩形/多边形/圆形 + 保存即审核开/关）、六页两主题、主题往返全部通过，`tests/workflow` **27 项通过**。

## 预标注后“接纳候选就存不上”的真因（2026-10-17）

用户更正：不是多边形画不出来，而是**预训练生成候选之后**再标注就存不上。用用户自己的项目（`我的项目/猫狗识别`，含 `proposals/latest`）在副本上复现，抓到真实报错：

```
shutil.copy2(destination, backup)
FileNotFoundError: [WinError 3] 系统找不到指定的路径。
```

`accept_proposal()` 与 `save_annotation()` 在覆盖已有标注前会先备份到 `backups/`，但 `shutil.copy2` **不会创建目标目录**。只要 `backups/` 不存在（项目移动/复制时漏掉、被手工清理），这一步就抛 `WinError 3`：

- 「接纳候选并微调」看起来像没反应，并弹出该错误；
- 随后编辑器的 `dirty` 一直为真，保存也不再落盘 —— 用户看到的“无法保存”。

修复：新增 `Project.backup_annotation()`，备份前 `mkdir(parents=True, exist_ok=True)`；`accept_proposal()` 与 `desktop.save_annotation()` 都改走它。回归测试新增 `test_accept_proposal_recreates_a_missing_backup_folder`（先删掉 `backups/` 再接纳与保存），workflow 测试合计 **28 项通过**。

界面文案同步修正：画布标签与对象列表原先一律显示「类别 · 实例 N」，在检测/分割项目里容易被当成另一种标签。现在**只有姿态任务**显示实例号（也只有姿态需要把框与骨点分组），其余任务直接显示类别名。

## 旋转框无法转满 360°（2026-10-17）

用户反馈旋转框转不满一圈。用探针实测定位到**两个独立原因**，都出在贴边/占满画面的大框上：

1. **手柄被画到画布外**：旋转手柄固定放在“框短边中点向外的 25px”处。当框贴着图片上边缘（或几乎占满画面）时，这个位置落在画布**之外**，点击根本到不了 canvas，于是完全转不动（实测角度恒为 0，12 次采样 `distinct=1`）。
2. **超出图片边界就被拒绝**：`move()` 里的旋转分支原先要求旋转后的四个角**全部**在图片内，否则整次旋转被丢弃。框转到 45° 时包围盒会变大，靠边的框一转身就越界，于是转到一半就“卡住”。

修复：

| 位置 | 改动 |
| --- | --- |
| `rotationHandle()` | 手柄若会落到画布边缘之外，就**向内翻转**到框的另一侧，保证永远可点 |
| `move()` 旋转分支 | 角度**无条件应用**，然后若整体越界就把框平移回画面内（而不是丢弃这次旋转）；同时顺手写入 `direction` |
| `down()` | 点击落在图片外时，若命中的是旋转手柄仍可开始旋转（手柄在画布内、但对应的图像坐标可能越界） |
| `move()` 夹取 | 旋转过程中**不再夹取指针**，否则贴边框的角度会被锁死 |
| `validate_annotation()` | 坐标允许有 **1px 容差**，旋转后的框贴在边缘也不会被“坐标超出图片”挡下 |

实测（同一个框三种摆放，指针绕中心扫一圈 12 个采样点）：

| 摆放 | 修复前 | 修复后 |
| --- | --- | --- |
| 画面中央 | 12 个角度 | 12 个角度 |
| 贴住上边缘 | **1 个角度（卡死）** | **12 个角度** |
| 几乎占满画面 | **1 个角度（卡死）** | **12 个角度** |

另外直接驱动旋转数学做了精确校验：指针 0/15/30/…/345° 对应形状 0/15/30/…/345°，**逐一对应、无跳变、可转满 360° 双向**。旋转后的框正确写入 `direction`。
