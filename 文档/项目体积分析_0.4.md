# 0.4 项目体积分析与清理记录

记录时间：2026-10-16。检查方式：目录递归求和 + 硬链接去重（按 `st_dev`/`st_ino`）+ 大文件 SHA256 + 安装器/DEB 头部结构核对 + 删除前逐字节可还原实测。

## 一、占用口径修正

首次统计按目录递归相加得到 64.03 GiB，**该口径把硬链接重复计数了**。按文件索引去重后：

| 口径 | 大小 |
|---|---|
| 路径累加（首次报告的 64.03 GB） | 64.03 GiB |
| **硬链接去重后真实占用** | **53.63 GiB** |
| 被重复计算的部分 | 10.40 GiB（涉及 31,657 个文件实体） |

硬链接链（`fsutil hardlink list` 确认同一文件实体三处指向）：

```
.packaging/uv-cache/archive-v0/bM74m77jE7syr35v/torch/lib/libtorch_cuda.so
.packaging/linux-python/lib/python3.12/site-packages/torch/lib/libtorch_cuda.so
.packaging/stage-linux-0.4.0/resources/workbench/.runtime/linux-python/.../libtorch_cuda.so
```

`uv-cache` 与 `linux-python` 之间几乎所有文件都是硬链接（uv 从缓存硬链接进环境），因此**删掉 `uv-cache` 只能释放 0.12 GiB，删 `linux-python` 只能释放 0.11 GiB** —— 两者都无清理价值，已从清单剔除。Windows 侧（`.venv` / `stage-windows` / `installed-windows`）**没有硬链接**，那里的重复是真实的磁盘重复。

## 八、附：本次遇到的文件权限问题

受沙箱约束的进程在**工作区子目录**内写入被拒（根目录正常）。原因：工作区根目录上有两条**非继承**权限项 —— `Everyone` 拒绝 `DeleteSubdirectoriesAndFiles`（DSH 预期设置）与会话身份 `S-1-4-188662058-875461850` 的写入许可；而子目录只有继承来的 `Authenticated Users: 修改`，缺少 `WRITE_OWNER`，DSH 无法把写入许可投放进子目录。

已用 DSH 自带的 `diagnose-windows-sandbox-acl.ps1` 修复（只改权限、不动文件内容与所有者），已验证通过。备份与回滚记录位于 `E:\大学\项目\dsh-acl-recovery\`，回滚命令：

```
pwsh -NoProfile -File 'E:\大学\项目\dsh-acl-recovery\acl-backup-b1dc54391b414f5e95a74a379ffbf0c1.json.ps1' -Path 'E:\大学\项目\yolo标注训练一体化\.packaging' -AllowRoot 'E:\大学\项目\yolo标注训练一体化' -Restore 'E:\大学\项目\dsh-acl-recovery\acl-backup-b1dc54391b414f5e95a74a379ffbf0c1.json'
```

## 九、后续建议

1. 发版后立即清理 stage 目录与中间归档，或在 `build_release.py` 增加 `clean` 子命令，避免逐版叠加数 GB。
