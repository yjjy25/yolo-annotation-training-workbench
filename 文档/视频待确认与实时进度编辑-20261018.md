# 视频待确认与实时进度编辑

本次修改已应用到本地源码。新导入的追踪视频使用以下流程：

**视频追踪 → 视频待确认区微调 → 确认当前帧 → 加入数据集。**

## 视频结果先在视频追踪中查看

视频帧和标注保存在项目的 `video-work/`，与数据集的 `images/`、`annotations/` 分开。保存视频草稿、完成追踪、设置遮挡、跳过骨点都不会增加数据集图片数。

在视频画布中，左侧导航保持“视频追踪标注”，缩略图显示当前附近的视频帧及“待确认 / 已加入”状态。视频列表保存处理进度、已保存画面数和已加入数据集的数量。

检查并微调后，点击顶部 **“确认当前帧，加入数据集”**。只加入当前这一帧，标为已审核；再次确认同一内容不会重复加入。视频工作副本保留以便继续检查；数据集副本独立，名称以 `reviewed_` 开头并保留来源。已加入的帧如需继续修改正式版本，应在数据集操作，避免无意覆盖已确认结果。

## 不跳帧播放时拖动和编辑

- 进度条按原始帧编号定位，不再只按抽帧后的序号。
- 播放时进度条仍可操作。开始拖动会停止追踪，拖动过程中会更新定位画面；原始帧打开后即可拖动框、轮廓或骨点微调。
- 已追踪但未按保存间隔抽出的原始帧也会保留预测坐标；首次查看时解码对应画面。没有追踪过的位置显示空标注，不猜测目标位置。
- 来回拖动后，人工修改仍保留。点击“保存当前帧并继续”，会使用当前修正作为新的追踪起点。
- 新起点之后的自动结果先归档，再重新计算；人工修改帧和已确认帧受保护，追踪遇到它们会暂停，等待检查。归档保存在 `video-work/backups/retrack_*/`，不直接删除先前结果。
- 遮挡状态、实例编号和跳过点保持不变。追踪失效的问题帧仍需人工处理，不会自动写入猜测标签。

播放原始帧与最终保存图片的间隔仍分开。确认前的视频草稿不参与训练。既有已经位于数据集的旧版视频帧保留原位置，不会自动搬移用户的已存数据。
