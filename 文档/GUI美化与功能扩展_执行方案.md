## 2. 界面设计方向

### 2.1 视觉主题：以画布为中心的视觉标注工作台

最突出的视觉元素是“图片上的目标框、骨点和当前标注提示”。界面控制区保持安静、清晰，让用户把注意力放在图片和下一步动作上。

- 默认浅色控制面板，搭配中性深灰画布；画布明暗可单独切换，便于查看不同素材。
- 蓝色表示当前操作与主按钮；审核状态同时使用文字和图标，不只靠颜色。
- 顶部展示任务进度，侧边展示图片、实例和骨点，不把工作区变成统计卡片页。
- 表单左对齐，数值和单位清楚排列；标注画布占据主要空间。
- 新手模式突出当前动作；高级参数按组展开。
- 使用适量边框和留白表达层级，减少装饰阴影、渐变与无关动画。

### 2.2 与其他方向的比较

| 方向 | 优点 | 取舍 |
| --- | --- | --- |
| 全深色专业工具 | 画面集中，适合部分长期使用者 | 首版先做好浅色控制区与可切换画布，完整深色主题后续补齐 |
| 大量圆角统计卡片 | 概览直观 | 只在项目概览中少量使用；标注页面保留紧凑工具结构 |
| 浅色工具区 + 独立画布 | 参数易读、操作清楚、适合新手 | 采用为主方向，重点验证图片与骨点的对比度 |

### 2.3 设计复核后的调整

初步结构容易把数据、训练、模型分别做成许多独立页面。为避免用户频繁跳转，调整为：标注与审核共用原画布；训练继续使用原训练窗口；项目概览负责引导，骨架编辑器负责一次性配置。视觉辨识度集中在“骨架点选提示与画布辅助显示”，其余控件保持统一。

## 3. 可直接落地的设计规范

### 3.1 核心颜色

| 名称 | 色值 | 用途 |
| --- | --- | --- |
| 工作区底色 | `#F3F6FA` | 页面底层和面板间隙 |
| 面板底色 | `#FFFFFF` | 表单、工具区、对话框 |
| 正文颜色 | `#182B45` | 主文字、标题 |
| 次级文字 | `#52647B` | 帮助文案、字段说明 |
| 操作蓝 | `#245BC4` | 主按钮、选中项、键盘焦点 |
| 画布深灰 | `#30363D` | 图片外围背景，独立于控制区主题 |

补充语义色：通过 `#16734B`，提醒 `#946200`，错误 `#B42332`。这些是设计初值，需对实际文字、底色、禁用态和焦点态进行对比度检查后定稿。

类别色、左右骨点色和审核状态色分别管理；不能因为某类别恰好是绿色，就被误认为已审核。骨点使用描边、点名和左右标记辅助辨认，必要时提供局部对比底。

### 3.2 字体、间距与组件

- Windows 优先使用系统“微软雅黑”，Ubuntu 优先 Noto Sans CJK SC；以系统可用字体回退，不默认联网加载字体。
- 如需打包字体，先核对许可证；在两平台验证中文和数字的度量差异。
- 正文建议 14～15 逻辑像素，辅助文字不小于 12；页面标题 22，分组标题 16。最终随平台字体和高 DPI 实测调整。
- 基础间距采用 4、8、12、16、24；表单和工具栏遵循统一对齐。
- 常规按钮高度建议 34～38 逻辑像素；小图标按钮保持足够点击面积并提供中文提示。
- 输入框圆角约 4，面板约 6，弹窗约 8；不为所有控件强制同一种大圆角。
- 一个操作区域突出一个主动作；删除、覆盖和停止等操作采用明确的文字与状态区分。
- 禁用按钮旁提供原因，例如“至少需要可用的训练集与验证集”。

### 3.3 控件必须定义完整状态

每个按钮、列表和输入框需覆盖：正常、悬停、键盘焦点、按下、选中、禁用、错误、处理中。后台任务必须有可感知的状态和取消/停止语义；不能只改变按钮颜色。

## 4. 页面与面板设计任务

### 4.1 项目概览和首次引导

保留“新建项目、继续上次项目、打开示例项目”三项主要动作。已有项目展示已审核、待审核和未标注数量，并根据实际状态提示下一步。

向导分为：选择任务 → 导入图片 → 定义类别/骨点 → 完成首张标注。每步只要求当前必要的信息，保存后可返回调整；不强迫用户首次使用就决定全部训练参数。

### 4.2 标注主工作区

```text
┌─────────────────────────────────────────────────────────────────┐
│ 原菜单 / 项目名 / 保存状态 / 新手模式                            │
├─────────────────────────────────────────────────────────────────┤
│ 导入 → 定义标签 → 人工标注 → 训练 → 自动标注 → 审核               │
├─────────────┬───────────────────────────────┬───────────────────┤
│ 图片与筛选  │ 原标注画布                    │ 实例 / 骨点       │
│ 未标注 70   │                               │ 机械臂五点 v1     │
│ 待审核 12   │ 当前骨点：肘关节              │ ✓ 底座            │
│ 已审核 18   │ 下一步：在图片上点击对应位置  │ ✓ 肩关节          │
│             │                               │ ● 肘关节          │
│             │ 图片、目标框、骨点与辅助连线  │ ○ 腕关节          │
│             │                               │ ○ 夹爪中心        │
├─────────────┴───────────────────────────────┴───────────────────┤
│ 撤销 / 位置未知 / 标记遮挡             保存实例 / 审核并下一张   │
└─────────────────────────────────────────────────────────────────┘
```

数量仅为原型示例，不代表当前项目实际数据。

使用可拖动分隔条；建议左栏初宽 220、右栏初宽 280 逻辑像素，按窗口宽度约束，优先给画布空间。较窄窗口先折叠帮助说明和次要栏，不让表单或按钮覆盖图片。

### 4.3 骨架模板编辑器

左侧是骨点名称和顺序列表，中间是可点击示意图，右侧是连线、左右配对及模板属性。提供“添加骨点、连接两点、预览点选顺序、保存模板”。

删除骨点时展示受影响的连线和现有数据；已用于标注的模板生成新版本。用户可以在保存前用一张示例图试标，减少建立错误顺序后返工。

### 4.4 训练配置与进度

沿用原训练窗口，按“数据检查 → 训练配置 → 训练结果”组织。新手配置先展示任务、模型、设备、轮数、图片尺寸、批大小和学习率，高级项折叠。

设备显示“CPU”或“GPU 名称 + 可用状态”；内部设备编号放在帮助信息中。数据区明确显示实际用于训练/验证的数量，AI 待审核结果不算作可训练数据。

训练中显示轮数、日志和曲线；停止按钮写“停止训练”，不要写“暂停”。结果页的主动作是“预览自动标注”，并显示模型、类别和骨架模板是否匹配。

### 4.5 自动标注与审核

先选择模型和范围，预览少量图片，确认后运行批量任务。AI 候选在原画布叠加显示，候选样式区别于人工正式标注，并提供图例。

审核操作分成“接受候选”和“审核整张图片”。接受一个预测不代表整图无漏检；整图通过后才改变审核状态。图片列表支持低置信度、空预测、骨架异常和随机抽查筛选。

### 4.6 空状态、失败和异常情况

| 情况 | 界面文案与动作 |
| --- | --- |
| 没有图片 | “先导入图片，开始建立标注项目。”＋“选择图片文件夹” |
| 尚无骨架 | “先定义需要标注哪些位置。”＋“创建骨架模板” |
| 没有训练环境 | “尚未准备训练环境。”＋“准备应用专用环境” |
| GPU 不可用 | 展示实际检测原因＋“重新检测”“使用 CPU” |
| 标注有错误 | 展示图片名、错误骨点及“打开并修正” |
| 模板与模型不匹配 | 列出不一致项＋“选择匹配模型” |
| 预测为空 | “模型未找到目标，请检查是否漏检。”＋“人工补标”“确认无目标” |
| 文件保存失败 | 显示具体原因，保留当前编辑与待保存状态，提供重试/另存 |

## 5. Qt 原工程的实施方式

### 5.1 先统一主题，再接页面

在原项目主题机制上增加颜色、字号和间距变量，避免每个窗口各写一套样式。QSS 只管理原生控件；骨架线、候选框、点名和选中效果通过画布的绘制逻辑实现。

建议新增模块，具体路径在锁定源码后确认：

```text
anylabeling/views/workflow/
  design_tokens.py           # 主题参数与语义色
  theme.py                   # 对接原主题与控件样式
  project_wizard.py          # 新手向导
  skeleton_editor.py         # 骨架编辑器
  pose_panel.py              # 顺序点选面板
  review_panel.py            # 候选与审核面板
  components/                # 提示条、状态标签和分组表单
```

原 `label_widget.py` 只增加菜单、面板挂载和信号连接；原 `canvas.py` 增加必要的辅助绘制与事件扩展。训练窗口沿用 `views/training/ultralytics_dialog.py`，业务仍走原训练服务。以上是接入计划，不代表文件已经创建或代码已经实现。

### 5.2 交互与业务的边界

- 点击按钮触发明确业务动作，只有保存或任务提交成功后才更新成功状态。
- 原型中的模拟进度必须标明演示；真实应用使用真实任务事件，不能循环假进度。
- 训练和批量推理不阻塞主界面；GPU 资源冲突通过排队处理。
- 原软件快捷键先建立清单，再决定新增快捷键，避免同一键在同一上下文触发两种动作。
- 编辑、撤销和审核均需要与正式标注事务一致；不能只更新画面上的状态标签。
- Windows 和 Ubuntu 的窗口布局分别保存，迁移项目时不复用无效的设备和解释器路径。

## 7. GUI 验收标准

- [ ] 界面依然运行在 X-AnyLabeling 原工程中，保留原画布和已用标注格式。
- [ ] 新手不手写 YAML 或寻找解释器，即可按引导完成受支持流程。
- [ ] 骨点顺序、当前骨点、未知/遮挡和实例归属一眼可辨。
- [ ] 关键操作同时有文字说明，不依赖颜色或纯图标表达含义。
- [ ] 浅色模式正文对比度目标至少 4.5:1，焦点与关键图形目标至少 3:1；实际测量通过后记录结果。（浅色中性色已按此目标重设，辅助文字实测 7:1 以上，见《验证记录.md》）
- [ ] 图片过亮、过暗或背景复杂时，骨点和框仍可辨认，并提供辅助显示选项。
- [ ] 在 1366×768 与 1920×1080 下检查主路径；Windows 100%/125%/150% 缩放及 Ubuntu 实际缩放环境分别检查。Windows 200% 缩放已在本机验收（帧纹理缩放 2.0、面板尺寸一致、主题往返正常，见《验证记录.md》）；125%/150% 与 Ubuntu 缩放仍待验证。
- [ ] 控件没有中文截断、按钮重叠、下拉框遮挡和对话框超出可用屏幕的问题。
- [ ] Tab 焦点顺序合理，键盘操作能看到焦点，关闭弹窗后焦点回到合适位置。
- [ ] 训练、导出和批量标注有真实进度/状态，取消与停止后的结果明确。
- [ ] 已审核标注被修改后重新进入待审核；接受 AI 候选不会直接冒充整图审核完成。
- [ ] 异常和空状态有下一步入口；失败不伪装成成功，未保存内容不被界面切换丢弃。
- [ ] 至少 3 位新手试用，至少 2 位仅靠界面在 10 分钟内完成建项目、自建 5 点模板及首张标注；不含安装、下载、训练时间。
- [ ] 与原版对照验证画框、拖动、缩放、撤销、保存、导出和图片切换。
